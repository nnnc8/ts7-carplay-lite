## Current adapter and deployment scope

The implementation now has real source seams, not a complete automatically enabled receiver. These observations are from the target files, separately from immutable upstream findings:

- [`XcertplayAdapter.runBootstrap:43–68`](../receiver-core/src/main/kotlin/io/ts7/carplay/core/XcertplayAdapter.kt#L43-L68) owns an already connected, user-selected RFCOMM socket. It waits for iAP2 readiness and uses `Iap2WirelessControlClient.onAuthenticated` for actual phone AA05, rather than treating provider availability/signing return as phone authentication.
- [`acceptAirPlay:89–136`](../receiver-core/src/main/kotlin/io/ts7/carplay/core/XcertplayAdapter.kt#L89-L136) gates the accepted local endpoint on network/AA05 state, config bounds, and a generated pairing identity; ported [`AirPlaySession.kt:331–354`](../receiver-core/upstream/xcertplay/src/com/shilapi/xcertplay/airplay/AirPlaySession.kt#L331-L354) refuses plain unauthenticated RECORD with 403 and requires MFi-SAP success, PairVerify-derived controller state and cipher before session-active callback. This is source behavior plus a reported host negative fixture, not a real-phone handshake result.
- [`Api27WirelessTransport.java:57–117`](../receiver/src/main/java/io/ts7/carplay/Api27WirelessTransport.java#L57-L117) implements LOHS and same-LAN choices, explicit Wi-Fi `Network` / address selection and loss watching. The LOHS reservation's missing `Network` yields `HOTSPOT_READY_UNBOUND`, not BOUND, authentication or streaming. Whether the TS7 can expose an appropriate downstream `Network`/address is **UNKNOWN**; an unrelated Wi-Fi `Network` must not be substituted. A separately reviewed OEM address-scoped backend may be needed.
- [`LawfulReceiverCore.java:11–25,47–56`](../receiver/src/main/java/io/ts7/carplay/LawfulReceiverCore.java#L11-L56) calls the configuration seam `Deployment`; the implementation update calls it AppDeployment. Its default constructor deliberately supplies null. The missing provisioned provider, OEM identity and Bonjour/endpoint configuration are not filled with invented values. API27 packaging does not turn this into an enabled session.
- [`XcertplayAdapter.kt:100–125`](../receiver-core/src/main/kotlin/io/ts7/carplay/core/XcertplayAdapter.kt#L100-L125) uses the existing H264 sink; audio forwarding is explicitly deferred and microphone is disabled. Imported pure codecs/protocol types do not prove decoded audio, Siri or input acceptance by an iPhone.
